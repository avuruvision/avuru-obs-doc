# Installer Avuru Obs et découvrir sa première carte

Commencez sur un cluster de test. eBPF découvre le trafic pris en charge sans
modifier les applications ; OpenTelemetry complète la collecte selon vos besoins.
Le temps de démarrage dépend du cluster, du téléchargement des images et du trafic.

## 1. Vérifier les prérequis

Vous avez besoin de Helm, d’un contexte Kubernetes accessible, d’un stockage
persistant pour ClickHouse et de nœuds Linux compatibles avec le sensor.
Consultez les [prérequis Kubernetes](/docs/setup/kubernetes/#requirements).
La collecte eBPF demande des permissions au niveau du nœud : vérifiez les
contraintes de sécurité de votre cluster.

## 2. Installer

<InstallSelector options={['Kubernetes', 'Docker', 'VM']} defaultOption="Kubernetes" />

Le chart réunit le sensor, la gateway, le hub, l’interface et ClickHouse.
L’exemple utilise une [version publiée](https://github.com/avuruvision/avuru-obs/releases).
Docker permet une évaluation locale ; le parcours VM repose sur votre pipeline OTLP.

## 3. Ouvrir l’interface

```bash
kubectl -n avuruobs port-forward svc/avuruobs-ui 8080:80
```

Ouvrez **http://localhost:8080/** et sélectionnez le projet qui reçoit les données.
Générez du trafic vers une application prise en charge : une carte vide sur un
cluster inactif n’indique pas forcément une panne de collecte.

## 4. Vérifier

```bash
kubectl -n avuruobs get pods
```

Vérifiez la disponibilité des composants, puis un service dans la carte et une
trace récente. Si ClickHouse reste en attente, examinez le PVC et la StorageClass.
Si aucun signal n’arrive, vérifiez les permissions et logs du sensor, la
compatibilité noyau/protocole et le projet sélectionné.

## 5. Envoyer votre OTLP existant

Depuis un autre namespace Kubernetes, utilisez le nom DNS complet :

```bash
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://avuruobs-gateway.avuruobs.svc.cluster.local:4318/v1/traces
```

Cet endpoint concerne OTLP/HTTP. Le transport gRPC utilise le port 4317 avec sa
configuration SDK correspondante. Consultez le [guide OTLP](/docs/setup/otel-bridge/)
pour les clés d’ingestion, le double export et les autres signaux.
