# Installer Avuru Obs sur Kubernetes

Le chart Helm déploie le DaemonSet sensor, la gateway, le hub, l’interface et
ClickHouse. Il est publié en OCI sur GHCR : aucun dépôt Helm à ajouter.

## Prérequis {/* #requirements */}

- Kubernetes ≥ 1.26 et Helm ≥ 3.8 avec prise en charge OCI.
- Nœuds Linux compatibles eBPF avec BTF, généralement noyau ≥ 5.8.
- Permissions nécessaires à la collecte du sensor sur les nœuds.
- StorageClass par défaut pour le volume persistant de ClickHouse.

Un noyau non compatible peut empêcher la collecte eBPF ; un pipeline OTLP peut
fournir les signaux indépendamment de cette collecte. Vérifiez les contraintes
de votre environnement plutôt que de supposer une couverture complète.

## Envoyer l’OTLP

Dans le namespace `avuruobs`, le nom court `avuruobs-gateway` suffit. Depuis un
autre namespace, utilisez `avuruobs-gateway.avuruobs.svc.cluster.local` :

- OTLP/HTTP : port 4318 ; les endpoints spécifiques de signal ont un chemin `/v1/traces`, `/v1/logs` ou `/v1/metrics`.
- OTLP/gRPC : port 4317, avec la configuration gRPC du SDK ou collecteur.

Le [guide OTLP](/docs/setup/otel-bridge/) couvre aussi les clés d’ingestion.

## Ouvrir l’interface

```bash
kubectl -n avuruobs port-forward svc/avuruobs-ui 8080:80
```

Ouvrez **http://localhost:8080/**. L’interface est un composant distinct ; son
origine relaie `/api` vers le hub. Pour un accès permanent, configurez ingress,
TLS et l’authentification selon votre environnement.

## Vérifier et dimensionner

Contrôlez les pods, le PVC et l’apparition de données récentes après avoir
généré du trafic. Une carte vide demande de vérifier projet, permissions,
compatibilité et pipeline avant de conclure à l’absence de services.

- [Stockage et rétention](/docs/operations/scaling/) : dimensionnement et haute disponibilité.
